# LinkedIn Launch Post — Design Patterns Series

## Post

PR reviews are taking senior devs more time than ever.

A PR with 400 lines of AI-generated code lands. Tests pass. Linter clean. No bugs. You approve it.

Two sprints later, that module is the one nobody wants to touch.

AI writes code that works — but doesn't hold up. It solves the ticket and creates three structural problems. Duplicated logic. God objects. Tight coupling hidden behind clean syntax.

The bottleneck in software development used to be writing code.
Now it's reviewing it.

Reviewing AI output isn't the same as reviewing a colleague's work. You're not catching typos or missing null checks. You're checking architecture. You're asking: does this structure survive the next five changes?

That takes one thing most of us haven't seriously revisited since university: design patterns.

The Gang of Four described 23 patterns in 1994. Thirty years later, they're still the fastest way to spot structural problems in a PR — whether a human or an AI wrote it.

I'm starting a series to make them practical again.

23 patterns — why they exist, when to reach for them, and how to apply them — all built into a smart home app as the running example.

Here's the repo that will hold the code for every pattern: https://github.com/KarimBelhworthy/design-patterns

First up: the Creational patterns.

Follow along. Drop a pattern you'd like me to cover first.
